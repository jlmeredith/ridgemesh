name: ridgemesh-remote-verification
description: Verify RidgeMesh numerical behavior, registered imagery and deployed browser flows on z370, preserving provenance and normalizing screenshots.
---

Use from an isolated RidgeMesh git worktree. Never run tests, builds, browsers or GIS processing on the Mac.

1. Run `npm run check:remote` to transfer the snapshot and run clean dependency installation, typecheck, lint, tests and build on z370. Preserve host, run ID and revision printed by the runner.
2. For browser acceptance, copy the current harness to the remote checkout and run Node 24 there with `RIDGEMESH_RUN_ID`, `RIDGEMESH_REVISION` and `RIDGEMESH_BROWSER_URL=https://ridgemesh.vercel.app`. Execute `timeout 480 node scripts/terrain-scenarios-browser-check.mjs`. Omitting BROWSER_URL starts a temporary remote dev server; never describe that run as deployed verification. Earlier browser harnesses preserve historical evidence and have outdated UI assumptions.
3. Keep browser runs isolated when measuring performance. Inspect `artifacts/<run>/browser-report.json`; require all current checks (22 in the terrain-scenario release before any later additions), actual deployed revision, no console errors and no failed requests. Each of the three original imagery assets must have a completed HTTP200 response and successful positive-dimension decode before switching sources. For 3D, also require the canvas imageryLoaded and positive imageryDimensions evidence. Merely changing an SVG href does not prove the image loaded; rapid switching once hid two aborted requests in an otherwise passing run. Check actual 1× terrain and antenna geometry, all default layers, landscape and event heat extents, legible mobile labels without overlapping map controls, R1-only and existing-ID alternate scenarios, unchanged preview persistence, move/height recalculation, mandatory P1 startup, scale down/up, actual primary relocation, fixed versus roaming semantics, optional G3 offer/roles, physical locks and inventory identities, preservation of roaming test nodes, original bytes on explicit legacy import, rejected ID collisions, independent layers, mast application, alternatives, late preview responses, persistence, empty plans, quota recovery and mobile. Independently verify the optimizer against exhaustive one-device and two-access-node oracles; a label or hard-coded scaffold does not prove a computed plan. Separate cold worker creation/network time from reported calculation time. Do not claim a strict latency target from a different metric.
4. Capture only scoped app elements. Normalize each raw capture using `scripts/normalize_screenshot.py` on the remote host before viewing; read the script's CLI help, parse its JSON, and expose only a successful normalized output path. Remote terrain Python with Pillow is `/home/jamie/ridgemesh-terrain-20260912/venv/bin/python`.
5. Record deployment ID, commit, canonical URL, test/browser evidence, source/model versions and rollback deployment in `docs/TERRAIN-SCENARIOS-RELEASE-2026-09-13.md`. The preceding correction record retains the event-site/source rationale. Keep unsurveyed vectors, partial ground-control evidence and absent field calibration explicit. The generated starter is best found under bounded constraints, not a global optimum or a field guarantee. Release coverage only as Planning estimate until actual observations justify stronger claims.
