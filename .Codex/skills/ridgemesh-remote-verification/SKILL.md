description: Verify RidgeMesh numerical behavior, registered imagery and deployed browser flows on z370, preserving provenance and normalizing screenshots.
---

Use from an isolated RidgeMesh git worktree. Never run tests, builds, browsers or GIS processing on the Mac.

1. Run `npm run check:remote` to transfer the snapshot and run clean dependency installation, typecheck, lint, tests and build on z370. Preserve host, run ID and revision printed by the runner.
2. For browser acceptance, copy the current harness to the remote checkout and run Node 24 there with `RIDGEMESH_RUN_ID`, `RIDGEMESH_REVISION` and `RIDGEMESH_BROWSER_URL=https://ridgemesh.vercel.app`. Execute `timeout 480 node scripts/optimized-start-browser-check.mjs`. Omitting BROWSER_URL starts a temporary remote dev server; never describe that run as deployed verification. Earlier browser harnesses preserve historical evidence and have outdated UI assumptions.
3. Keep browser runs isolated when measuring performance. Inspect `artifacts/<run>/browser-report.json`; require all 22 current checks, actual deployed revision, no console errors and no failed requests. Each of the three original imagery assets must have a completed HTTP200 response and successful positive-dimension decode before switching sources. Merely changing an SVG href does not prove the image loaded; rapid switching once hid two aborted requests in an otherwise passing run. Check the applied router/base first view, independent layers without physical changes, basic-view editing protection, Customize, mast application, comparisons, optimization preview/apply, late worker responses after leaving Customize, exact persistence, legacy upgrade, deliberately empty plans, unreadable/quota recovery and mobile. Separate cold worker creation/network time from reported calculation time. Do not claim a strict latency target from a different metric.
4. Capture only scoped app elements. Normalize each raw capture using `scripts/normalize_screenshot.py` on the remote host before viewing; read the script's CLI help, parse its JSON, and expose only a successful normalized output path. Remote terrain Python with Pillow is `/home/jamie/ridgemesh-terrain-20260912/venv/bin/python`.
5. Record deployment ID, commit, canonical URL, test/browser evidence, source/model versions and rollback deployment in `docs/OPTIMIZED-START-RELEASE-2026-09-13.md`. The preceding correction record retains the event-site/source rationale. Keep unsurveyed vectors, partial ground-control evidence and absent field calibration explicit. The generated starter is best found under bounded constraints, not a global optimum or a field guarantee. Release coverage only as Planning estimate until actual observations justify stronger claims.
